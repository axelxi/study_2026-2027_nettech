Включим на маршрутизаторе msk-aeakunaeva-gw-02 интерфейс и снова пропингуем PC2 с PC1 - пакеты проходят. Посмотрим захваченный на соединениях трафик в Wireshark ([рис. @fig:015]-[рис. @fig:016]):

В окне Wireshark видны пакеты ICMP эхо-запросов и ответов, которые генерируются при выполнении команды ping между узлами 10.0.10.10 и 10.0.11.10. Для трассировки маршрута используются TCP-пакеты с флагом SYN, а также видны их повторные отправки при отсутствии ответа. Протокол ARP используется для разрешения MAC-адресов в локальной сети (запрос «Who has 10.0.11.10?»). Кроме того, в захвате присутствуют пакеты протокола RIPv2, которые маршрутизаторы периодически отправляют на multicast-адрес 224.0.0.9 для обмена таблицами маршрутизации. Также видно ICMP-сообщение «Time-to-live exceeded», которое возвращается при трассировке, когда счетчик TTL пакета достигает нуля на одном из промежуточных узлов.

![Восстановление интерфейса](image/13.PNG){#fig:015 width=70%}

![Трафик Wireshark](image/14.PNG){#fig:016 width=70%}

Теперь настроим на маршрутизаторах RIPng для сетей IPv6. Для PC1 про пингуем PC2 и определим путь следования пакетов. На msk-aeakunaeva-gw-01 проверим метки протокола RIPng ([рис. @fig:017]):

![Настройка RIPng протокола маршрутизаторов](image/15.PNG){#fig:017 width=70%}

Отключим на маршрутизаторе msk-aeakunaeva-gw-02 интерфейс eth0, проверим метрики протокола RIPng у msk-aeakunaeva-gw-01 и после пропингуем с PC1 PC2. Пакеты не будут передоваться, через время также не удалось восстановить маршрут ([рис. @fig:018]):

![Отключение интерфейса](image/16.PNG){#fig:018 width=70%}

Вернём работу интерфейса eth0 у маршрутизатора msk-aeakunaeva-gw-02 и снова пропингуем PC2 с PC1. Просмотрим трафик в Wireshark ([рис. @fig:019]):

Пинг между узлами 2001:10::a и 2001:11::a осуществляется с помощью пакетов ICMPv6 Echo. Трассировка маршрута в IPv6 использует UDP-пакеты, на которые промежуточные маршрутизаторы отвечают сообщениями ICMPv6 «Time Exceeded (Hop limit exceeded in transit)» при превышении лимита хопов, а конечный узел отвечает «Destination Unreachable (Port unreachable)». Для обмена маршрутной информацией в IPv6 применяется протокол RIPng, который рассылает обновления (Command Response, Version 1) на multicast-адрес FF02::9. Поскольку сеть использует двойной стек, в этом же захвате параллельно видны пакеты RIPv2 (адрес 224.0.0.9), которые продолжают обслуживать IPv4-маршрутизацию.
